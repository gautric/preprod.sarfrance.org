# Project Structure — Agenda

## Agenda Event Fields

Events in `data/agenda.yaml` use a single `date` field in ISO 8601 format:
- Date only: `"2026-01-17"`
- Date with time: `"2026-02-06T18:00:00"`
- Date interval: `"2026-03-03/2026-03-31"` (multi-day events)

Templates and JS parse the `/` separator for intervals and the `T` component for times automatically.

Additional fields:
- `title` — event title (French)
- `type` — event type key (matches `data/metadata/agenda.yaml`)
- `description` — short text shown on the card
- `location` — venue name
- `link` — external URL (wraps the title as a link)
- `lat` / `lon` — coordinates for the Leaflet mini-map on the card (set to `0` to suppress map)
- `photos` — optional: list of the event's photos in the photo gallery (`content/{fr,en}/activites/phototheque.md`), as file names without extension (e.g. `- "2026-09-ravivage-flamme-1"`). The first item is the scroll target, so list first the photo shown first in the gallery section of the event's year (photos filed under another year's section, e.g. `2020-07-picpus-1` shown in the 2021 section, go after). A photo belongs to one event at most (Hugo warns otherwise). Renders a "📷 Photos" link on the agenda card pointing to `/activites/phototheque/?event=<agenda event id>#photo-<first>` (language-aware via `site.GetPage`; the event id is the agenda card's `.tl-row` id, `<date>-<urlized title>`). The link is only rendered when the first photo is present in that language's gallery; every missing photo triggers a Hugo warning. Placed just before `update`. Not a substantive change: adding or editing `photos` does not bump `update` (and `scripts/agenda_update_dates.py` ignores it). Labels: `event_photos` / `event_photos_title` in `i18n/fr.yaml` and `i18n/en.yaml`; style `.agenda-card-photos` in `agenda.css`.
- `update` — technical field: date (`"YYYY-MM-DD"`) of the last substantive change to the event. Always last in the block. Drives the "Nouveau / New" badge.

All events should include the extended fields (`description`, `location`, `link`, `lat`, `lon`) whenever the information is available, regardless of date. For a physical venue, always provide `location` and the corresponding `lat`/`lon` coordinates so the Leaflet mini-map can render. Use `lat: 0` / `lon: 0` only for events with no physical location (e.g. videoconferences). Older events that still lack these fields should be completed as the information becomes available.

Photo gallery highlighting: `phototheque.html` gives each `.gallery-item` the id `photo-<file name without extension>` (first occurrence only, since a photo may appear twice) and, when an agenda event lists it in `photos`, `data-event="<agenda event id>"`. Thumbnails carry their intrinsic `width`/`height` (read with `images.Config`) so lazy loading does not reflow the rows and shift the target. On `?event=<id>`, `pages/phototheque.js` adds `.photo--highlight` to every matching photo, scrolls to the `#photo-…` target (or the first match) and fills the visually hidden `aria-live` region `.gallery-status` (labels `photo_highlight_one` / `photo_highlight_other`, `{n}` = count). Without JavaScript, the `#photo-…` anchor still scrolls to and outlines the first photo. Styles: `.gallery-item:target, .gallery-item.photo--highlight` (thick outline) and `.gallery-item[id]` `scroll-margin-top` in `phototheque.css`; colour `--photo-highlight` in `colors.css`.

## Agenda `update` Field, "Nouveau / New" Badge and Filter

- Every event in `data/agenda.yaml` carries a technical `update` field holding the date of its last substantive change (creation counts as a change). It is the last key of each event block.
- When adding or editing an event by hand, set `update` to the current date. Automated flows (`agent-agenda`, the `ajout-evenement-agenda` Kiro hook) do the same.
- The historical baseline was reconstructed from the git history of `data/agenda.yaml` (and its `data/agenda.json` predecessor) by `scripts/agenda_update_dates.py`. Re-run it with `make agenda-dates` (or `python scripts/agenda_update_dates.py --write`) to recompute every date from git; schema-only refactors are ignored by the comparison, so they do not reset the dates.
- `partials/event-is-new.html` is the single source of truth for the freshness rule: it returns `true` when `update` falls within `params.newEventDays` (15 days by default, in `config/_default/params.yaml`). Never re-implement the comparison — call the partial.
- `partials/event-new-badge.html` renders the badge via that partial. Used on the agenda pages (`activites/agenda.html`). The homepage upcoming-events cards (`index.html`) show no badge: they call `event-is-new.html` directly and add `.event-date--new` to the date block, which takes the `--event-new-bg` / `--event-new-text` colours (rule in `colors.css`).
- Freshness is computed at build time. The daily rebuild scheduled in `deploy.yml` (06:00 UTC) makes the badge and the filter expire on their own, so no client-side JavaScript is involved in the date logic.
- The agenda filter bar carries a "Nouveau / New" pill (`.filter-btn.filter-new`) with a count, rendered only when the displayed year holds at least one fresh event — same conditional pattern as `$usedTypes` for the type pills.
- Adding `?new` to an agenda URL preselects that filter (e.g. `/activites/agenda-2026/?new`). Any form works: `?new`, `?new=1`, `?a=1&new`. When the displayed year holds no fresh event the pill is absent and the page falls back to "Tout / All" rather than showing an empty list. `pages/agenda.js` implements this by clicking the pill, so the `FilterEngine` binding stays the single place that owns active-button and visibility logic.
- Agenda filter attributes: buttons carry `data-filter` (single value), rows carry `data-filters` (comma-separated: the event type, plus `nouveau` when fresh) and `pages/agenda.js` runs the shared `FilterEngine` with `multiValue: true`. The plural attribute name reflects that a row now holds several filterable values; do not put the freshness flag back into a `data-type` attribute.
- Styles: `.event-new`, `.filter-btn.filter-new::before` and `.filter-btn-count` in `filters.css`; colours `--event-new-bg` / `--event-new-text` plus the `.filter-btn.filter-new.active` override in `colors.css`; labels `event_new`, `event_new_title` and `filter_events` in `i18n/fr.yaml` and `i18n/en.yaml`.

## Adding an Event to a Personal Calendar

- Every (non-past) agenda card carries a "📅 Ajouter au calendrier / Add to calendar" button **placed just after `.agenda-card-location` (📍) and before `.agenda-card-photos` (📷)** in `.agenda-card-meta`. The trigger is now an **inline link-style button** sized like 📍 / 📷 (same font, same line-height — no full-width pill): `.agenda-cal` is `display: contents` so the button and its panel become direct flex items of `.agenda-card-meta`, while the panel keeps `flex: 1 1 100%` and wraps full-width below the meta line (staying in the flow, never clipped by `.page-card--has-map { overflow: hidden }`). The panel still offers **four entries, in this order**: (1) copy the event's absolute `.ics` URL, (2) Google Calendar, (3) Outlook, (4) iCloud (per-event `.ics` open/download). It opens on **button click, Enter/Space, and mouse hover** (fine pointers only); a double-click on the card body is an extra shortcut. Hover is never the only way in — the button is focusable and the links stay valid without JavaScript.
- **Hover opening with grace period**: on `(hover: hover)` pointers only, hovering the trigger or the open panel opens it; leaving schedules a ~1500 ms grace close (the `GRACE` constant in `pages/add-to-calendar.js`) so the pointer can travel from the button to the panel and the panel stays visible a moment after the pointer leaves. Because `.agenda-cal` is `display: contents` (no box of its own), `pages/add-to-calendar.js` binds the hover listeners to the button **and** the panel rather than the container. A panel opened by click is tagged `data-opened-by-hover` only when hover opened it, so a click-opened panel is never auto-closed by hover. One panel open at a time; Escape closes and returns focus to the button; an outside click closes.
- **Copy entry** (`.agenda-cal-copy`, a `<button>`): copies `new URL(data-ics-url, location.href).href` to the clipboard via `navigator.clipboard.writeText`, falling back to a temporary `<textarea>` + `document.execCommand('copy')` on non-secure contexts (e.g. `http://localhost`). Confirmation "Lien copié ! / Link copied!" shows for ~2 s in the `.agenda-cal-feedback` region (`role="status" aria-live="polite"`). This reuses the same clipboard pattern as the header calendar menu in `pages/agenda.js`.
- **Annual header menu** (`partials/page-header.html`, class family `.page-header-cal*`): the former single `.page-header-ics` copy-link icon is replaced by a **dropdown menu on the `page-contribute.html` model** — a round 36×36 `.page-header-cal-toggle` (calendar SVG) opening a `.page-header-cal-dropdown`, pure-CSS on `:hover` / `:focus-within`. On top of the CSS opening, `pages/agenda.js` adds a **4 s retention**: once opened (hover or keyboard focus) the menu keeps a JS-set `.page-header-cal.is-open` class (CSS selector `.page-header-cal.is-open .page-header-cal-dropdown { display: block }`, alongside the untouched `:hover` / `:focus-within` rules). On `mouseleave` / `focusout` a single `setTimeout` (≥ 4000 ms) is armed instead of closing immediately; at expiry it drops `is-open` only if the pointer is no longer hovering (`matches(':hover')`) and focus is not inside — otherwise it leaves the CSS path in charge and re-arms on the next exit. Re-entering (hover or focus) before the delay clears the timer and keeps the menu open. Escape closes immediately (drops `is-open`, `aria-expanded=false`, clears the timer) and returns focus to the toggle. `aria-expanded` stays `true` while `is-open` is present (mouse opening included) and flips to `false` when it is removed. (JS also performs the copy.) Its four entries subscribe to the **whole annual feed** (not a single event): (1) `.page-header-cal-copy` copies the absolute annual `.ics` URL (same clipboard mechanism, feedback in `.page-header-cal-feedback`); (2) **Google subscription** `https://calendar.google.com/calendar/r?cid=<webcal URL urlencoded>` (the `cid=<webcal>` form subscribes to the feed — `render?action=TEMPLATE` would only create one event, and `cid=<https ics>` is rejected by Google in practice); (3) **Outlook subscription** `https://outlook.live.com/calendar/0/addfromweb?url=<https ics>&name=<calendar name>`; (4) **iCloud / Apple** via a `webcal://www.sarfrance.org/activites/agenda-<year>/index.ics` link, marked `safeURL` so Hugo does not neutralise the non-standard scheme. External links carry `target="_blank" rel="noopener"` (iCloud keeps `rel="noopener"` without `_blank`, it is an app-scheme). The annual `.ics` `.Permalink` and the `icsMenu` flag are passed from `agenda.html` into `page-header.html`.
- **No button for the past** (computed at build time with `now`, never in JS): (a) per card, the button is skipped when the event's **end day** (`endDay` from `event-dates.html`, the non-exclusive end date, or the start day when there is no `début/fin` interval) is strictly before `now.Format "2006-01-02"` — same-day and ongoing events keep their button; (b) on a page whose displayed `$year` is **strictly earlier** than the current `currentAgendaYear` (`$yearIsCurrentOrFuture := ge (int $year) (int $agendaYear)`), **no** button is rendered at all — neither per card nor the header menu. A future year keeps every button.
- `partials/event-calendar.html` renders the per-card block. **The Google and Outlook URLs are built at build time**, not in JS: `querify` encodes accented titles, descriptions and venues, and `partials/event-dates.html` is the single source of the date normalisation. The `.ics` URL to copy is exposed in `data-ics-url` (made absolute client-side); the Google/Outlook/iCloud links stay valid without JavaScript. `pages/add-to-calendar.js` opens/closes the panel (click, Enter/Space, hover, double-click, Escape, outside click, `✕`) and performs the clipboard copy — never re-implement date parsing there.
- `partials/event-dates.html` returns `allDay`, `gDates`, `oStart` / `oEnd` / `oAllDay`, `icsStart` / `icsEnd`, `uidDate`, plus `startDay` and `endDay` (both `AAAA-MM-JJ`; `endDay` is the **non-exclusive** end used only for the "is it past?" test, distinct from the exclusive J+1 feed values). Rules: times in `data/agenda.yaml` are Paris times, converted to UTC (`…Z`) so no `VTIMEZONE` is needed; an all-day event uses an **exclusive** end date (J+1) for Google, Outlook and `DTEND;VALUE=DATE`; a start time without an end gets +2 h.
- `partials/event-ics.html` publishes the per-event file under `/calendars/<lang>/<AAAAMMJJ>-<urlized title>.ics` via `resources.FromString`. Its `UID` reuses *exactly* the annual feed's slug expression (`title | lower | replaceRE "[^a-z0-9]+" "-"`, **not** `urlize`), so a client that already imported the annual feed updates the event instead of duplicating it. Unlike the annual feed, this file escapes TEXT values (`partials/ics-escape.html`) and folds content lines to 75 octets (`partials/ics-fold.html`).
- The annual feed `activites/agenda.ics.ics` is **unchanged** and keeps its `TZID=Europe/Paris`: it remains the no-JavaScript path to the whole year, and the header calendar menu subscribes to exactly this feed.
- `pages/add-to-calendar.js` is loaded by `activites/agenda.html` in its `{{ define "scripts" }}` block, after `pages/agenda.js`. The double-click ignores `a, button, .agenda-cal, .page-card-map`, so linked titles, the "📷 Photos" link and Leaflet's double-click zoom keep their behaviour.
- Styles for the per-card block in `agenda.css`: `.agenda-cal` (`display: contents` — no box, so the button and panel are hoisted into the `.agenda-card-meta` flex line), `.agenda-cal-btn` (inline link-style trigger at the 📍 / 📷 gauge), `.agenda-cal-panel` (`flex: 1 1 100%`, wraps full-width in the flow), `.agenda-cal-copy` (bare `<button>` styled like a panel link, `🔗` icon), `.agenda-cal-link` + `--google` / `--outlook` / `--icloud` (`☁️` icon), `.agenda-cal-close`, `.agenda-cal-feedback` (copy confirmation). The panel stays **in the flow** rather than absolutely positioned: `.page-card--has-map` has `overflow: hidden` (`filters.css`), which would clip a popover. Under `max-width: 768px` the copy button and the links stack full-width to avoid overflow at ~375 px. Colours are `colors.css` variables only, so dark mode follows with no extra rule.
- Styles for the header menu in `style.css` (`.page-header-cal*`): they **reuse the `.page-contribute*` pattern** (round 36×36 toggle, absolutely-positioned dropdown `top: calc(100% + 8px); right: 0; display: none`, opened by `.page-header-cal:hover` / `:focus-within`). `.page-header-cal-copy` is a bare `<button>` sharing the dropdown link styling; `.page-header-cal-feedback` is the transient "copied" pill. The former `.page-header-ics*` rules are removed (no template emits that class any more). Colours are `colors.css` variables only.
- Labels in `i18n/fr.yaml` and `i18n/en.yaml`: `add_to_calendar`, `add_to_calendar_title`, `add_to_calendar_panel`, `cal_copy`, `cal_copied`, `cal_google`, `cal_outlook`, `cal_icloud`, `cal_close`, plus `cal_menu_label` (header-toggle `aria-label`), `copy_calendar_link` and `ics_copied` (header copy entry + feedback). The former `cal_apple` key is kept in both files but no longer referenced by any template (the entry became iCloud).
- Data attributes on the per-card panel: `.agenda-cal-btn[aria-controls]` / `aria-expanded` (panel id + open state), `.agenda-cal-btn[data-opened-by-hover]` (set by the JS when hover opened the panel), `.agenda-cal-copy[data-ics-url]` (relative per-event `.ics` URL) and `[data-copied-label]` (confirmation text). On the header menu: `.page-header-cal-toggle[aria-expanded]` and `.page-header-cal-copy[data-ics-url][data-copied-label]`.
- `.agenda-card-meta:empty { display: none }` still guards empty meta rows: past events keep their `.agenda-card-location`, so the line stays; a card with no location, no photos and no calendar button (none in practice) would collapse cleanly.
